REAL-TIME FRAUD DETECTION WEB APP - OVERVIEW

1) WHAT THIS WEBSITE DOES
This website is a fraud detection platform for digital transactions.
It helps analysts and demo customers simulate payments/transfers, score fraud risk in real time, and review suspicious activity.

At a high level, the app:
- Registers users and stores profile/location details
- Scores each transaction with a machine learning + rules engine
- Labels each transaction as APPROVE, REVIEW, or BLOCK
- Tracks device context, transaction velocity, and location mismatch signals
- Stores audit logs and transaction history for monitoring


2) MAIN PAGES
A) Analyst Dashboard (/)
- Sign in as an analyst
- Register or delete users
- Run fraud analysis (score a transaction)
- View recent transactions, review queue, and high-value alerts
- See current device/session context and system health

B) Customer Simulator (/customer)
- Simulates customer transfer flow
- Creates/selects customer profiles
- Looks up beneficiary account details
- Uses live browser location for transfer context
- Shows decision results and transfer history


3) CORE WEB APP FUNCTIONS
A) Authentication and Access
- Analyst login with JWT token session
- Protected analyst endpoints for sensitive operations

B) User Management
- Register new users with contact and address data
- Geocode user registration address (when available)
- List users and load user-specific transaction history
- Delete users and linked records

C) Fraud Scoring / Prediction
- Accepts transaction input (user, amount, merchant label, timestamp, device/location context)
- Builds fraud features from:
  - transaction amount/time
  - user history and velocity (1h/24h)
  - known/new device state
  - location mismatch and distance from home
  - VPN/proxy signal (IP intelligence)
- Produces:
  - fraud probability
  - risk level (LOW/MEDIUM/HIGH)
  - decision (APPROVE/REVIEW/BLOCK)
  - risk factors list

D) Device and Location Intelligence
- Generates or accepts device fingerprint
- Resolves location using browser geo, IP geo, profile, or defaults
- Compares transaction location against registered user location
- Tracks known devices per user over time

E) Monitoring and Operations
- Health endpoint for service/database/model status
- Dashboard aggregates (fraud rate, queues, alerts)
- Structured system logs and prediction records
- Recent activity and review queue for analysts

F) Data and Persistence
- PostgreSQL stores users, transactions, devices, predictions, and logs
- Model/scaler artifacts loaded for real-time inference
- Optional MinIO object storage integration


4) DECISION OUTCOMES
- APPROVE: low-risk transaction
- REVIEW: suspicious, needs analyst attention
- BLOCK: high-risk transaction likely fraudulent


5) TYPICAL FLOW
1. Analyst logs in
2. Analyst registers/selects a user
3. Analyst submits transaction details
4. Backend computes features and scores risk
5. App stores transaction + prediction + audit log
6. Dashboard updates review queue and analytics


6) WHO THIS APP IS FOR
- Final-year project/demo environments
- Fraud analytics experiments
- Security and risk simulation workflows


7) KEY BENEFITS
- Real-time fraud scoring
- Explainable risk factors
- User/device/location-aware decisions
- End-to-end flow: registration -> scoring -> review -> monitoring


8) HOW THE API WORKS
Base URL:
- Local Flask direct: http://localhost:5000/api
- Through nginx: http://localhost/api

Request/response pattern:
- Client sends JSON to an endpoint
- Backend validates fields and data types
- Business logic runs (DB lookup, feature engineering, model scoring)
- Backend returns JSON response with success/error info

Authentication model:
- Public/less-sensitive endpoints can be called directly (for example: health)
- Analyst endpoints require login token
- Login endpoint returns a JWT token
- Send token in header:
  Authorization: Bearer <TOKEN>

Typical analyst API sequence:
1. POST /auth/login
2. POST /register (create user)
3. GET /users (pick user_id)
4. POST /predict (score transaction)
5. GET /dashboard-data, /review-queue, /logs (monitoring)


9) JSON YOU CAN USE TO TEST THE API

A) Analyst Login
Endpoint:
- POST /api/auth/login

JSON body:
{
  "username": "analyst",
  "password": "YOUR_ANALYST_PASSWORD"
}

Expected:
- Returns token, use it as Bearer token in next protected requests.


B) Register User
Endpoint:
- POST /api/register

JSON body:
{
  "username": "jane_doe",
  "email": "jane@example.com",
  "phone_number": "+2348012345678",
  "address": "12 Allen Avenue, Ikeja, Lagos, Nigeria",
  "cardholder_age": 32
}

Expected:
- Returns success, generated user_id, and stored profile fields.


C) List Users
Endpoint:
- GET /api/users

Body:
- None

Expected:
- Returns users array. Copy one user_id for prediction tests.


D) Fraud Prediction (Analyst)
Endpoint:
- POST /api/predict

JSON body (minimum practical test):
{
  "user_id": "REPLACE_WITH_USER_ID",
  "amount": 2500.00,
  "merchant_name": "Clothing Purchase",
  "merchant_category": "Clothing"
}

JSON body (full context test):
{
  "user_id": "REPLACE_WITH_USER_ID",
  "amount": 2500.00,
  "merchant_name": "Clothing Purchase",
  "merchant_category": "Clothing",
  "timestamp": "2026-03-17T10:30:00Z",
  "device_fingerprint": "browser-ip-device-hash-001",
  "latitude": 6.5244,
  "longitude": 3.3792,
  "ip_country": "Nigeria",
  "ip_city": "Lagos"
}

Expected:
- Returns decision, risk_level, fraud_probability, risk_factors, and transaction_id.

Important amount rule:
- amount must be > 0 and <= 99,999,999.99


E) Dashboard Data
Endpoint:
- GET /api/dashboard-data

Body:
- None

Expected:
- Returns totals, fraud rate, review queue count, recent transactions, and alerts.


F) Review Queue
Endpoint:

G) Health Check

10) QUICK CURL/POWERSHELL TEST IDEAS
PowerShell login example:
$login = @{ username='analyst'; password='YOUR_ANALYST_PASSWORD' } | ConvertTo-Json
$auth = Invoke-RestMethod -Method Post -Uri http://localhost:5000/api/auth/login -ContentType 'application/json' -Body $login
$token = $auth.token

PowerShell prediction example:
$headers = @{ Authorization = "Bearer $token" }
$payload = @{
  user_id='REPLACE_WITH_USER_ID'
  amount=2500.00
  merchant_name='Clothing Purchase'
  merchant_category='Clothing'
} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://localhost:5000/api/predict -Headers $headers -ContentType 'application/json' -Body $payload
